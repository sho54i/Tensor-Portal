Article 01 — Cryptography

ZK-SNARK Folio

A proof system where one party can convince another a statement is true — revealing nothing beyond that truth itself. Compact, fast, and increasingly central to verifiable AI.

Ground Truth Series / Zero-Knowledge Proof Systems
01 — Core anatomy
Zero-Knowledge
Nothing Leaked
The verifier learns only that a statement is true. No witness, no secret, no input data is revealed. A prover can confirm knowledge of a private key without exposing it.
Succinct
Small Proofs
Proof size is O(log n) or constant — tiny relative to the computation. Verification is orders of magnitude cheaper than re-running the computation itself.
Non-Interactive
One Message
No back-and-forth challenge rounds. The prover sends a single proof string. Enabled by the Fiat-Shamir heuristic — transforming interactive protocols into offline artifacts.
Argument
Computational Soundness
Soundness holds against computationally bounded adversaries. A proof cannot be forged without solving a hard mathematical problem.
Knowledge
Witness Extraction
The prover demonstrably possesses a valid witness — not just that one exists. This is what separates a proof of knowledge from a proof of existence.
Trusted Setup
Common Reference String
Most SNARKs require a CRS — structured public parameters from a ceremony. If toxic waste from setup isn't destroyed, the system is compromised.

03 — AGI & cognitive system applications
Task handling
Verifiable task execution
An agent proves it ran a task correctly without revealing its private reasoning chain or weights. A coordinator verifies a subtask result without re-running it — enabling trustless agent delegation in multi-agent pipelines.
Memory architecture
Private memory attestation
A ZK proof attests that a memory retrieval was computed correctly over a private knowledge base. In a LAP-style memory system, external verifiers can confirm identity-core consistency without reading the document.
Alignment & safety
Constrained behaviour proofs
Prove an agent's output was generated within a constrained policy — without exposing the policy or model weights. An AGI system could publish a proof its decision satisfies alignment constraints, verifiable by any third party.
Identity & provenance
Entity identity anchoring
ZK proofs anchor an agent's identity across sessions without leaking history. An entity proves it is the same identity as a prior session — using a private identity witness — without replaying any prior context.
Multi-agent trust
Trustless knowledge sharing
Agent A proves to Agent B it derived a conclusion from a valid reasoning chain — without exposing the full chain. Epistemic trust without transparency: an agent coalition where each member attests to contribution quality.
zkML
Verifiable inference
The emerging zkML field encodes neural network inference as arithmetic circuits. ezkl, RISC Zero, and Modulus Labs demonstrate this today. Expensive, but falling fast with GPU acceleration.

05 — Crypto ecosystem
Active protocols
Zcash (Sapling / Orchard)
Private transactions using Groth16 then Halo2. Oldest production SNARK deployment. Proves spend validity without revealing sender, receiver, or amount.
zkSync / StarkNet
ZK-rollups for Ethereum L2. Prove batches of transactions off-chain, post one proof on-chain. Massively reduces gas costs while inheriting Ethereum security.
Polygon zkEVM
Proves full EVM execution in zero-knowledge. Any Ethereum contract runs with cryptographic verifiability. The technically hardest ZK project to date.
Semaphore / Worldcoin
ZK identity systems. Prove membership in a set without revealing which member you are. Privacy-preserving credentials at scale.
Proof system variants
Groth16
Smallest proofs, fastest verification. Requires per-circuit trusted setup. The gold standard for succinct proofs.
PLONK / Halo2
Universal setup — one CRS for all circuits. Halo2 adds recursive composition without a trusted setup via polynomial commitments.
STARKs
No trusted setup, post-quantum secure, larger proofs (~100KB). Transparency is the key advantage — hash-function based, no elliptic curve assumptions.
Nova / Folding schemes
Incrementally Verifiable Computation. Fold multiple computation steps into one proof without recursion overhead. Ideal for proving long sequential agent trajectories.
Article 02 — zkML

ezkl & Verifiable
AI Inference

How neural network layers become arithmetic circuits, what it costs to prove them, and where the frontier is moving.

Ground Truth Series / Verifiable Machine Learning
01 — What ezkl actually does

ezkl is a Python/Rust library that takes a neural network in ONNX format and compiles it into a ZK circuit using the Halo2 proof system. Every floating-point operation in a neural net is approximated as arithmetic over a finite field — ezkl handles that translation automatically.

The output is a proving key, a verification key, and a Solidity verifier contract. Anyone with the verifier key can check a proof in milliseconds, without access to the model weights or input data.

Weights can be kept private — the proof only attests to the structure of computation, not the values. The prover is the model owner; the verifier can be on-chain (Ethereum) or off-chain.

Install + basic workflow
# install
pip install ezkl

import ezkl

# 1. export model to ONNX
torch.onnx.export(model, dummy,
    "model.onnx")

# 2. generate settings
await ezkl.gen_settings(
    "model.onnx", "settings.json")

# 3. compile circuit
await ezkl.compile_circuit(
    "model.onnx", "model.compiled",
    "settings.json")

# 4. trusted setup (once per circuit)
await ezkl.get_srs("settings.json")
await ezkl.setup(...)

# 5. generate witness + prove
await ezkl.gen_witness(...)
await ezkl.prove(...)

# 6. verify anywhere — ms
await ezkl.verify("proof.json", ...)

04 — Proving cost factors

ZK circuits operate over finite fields — there are no floats. ezkl converts weights to fixed-point integers using a scale parameter (typically 7–16 bits of precision).

Nonlinear functions (ReLU, exp, softmax) require lookup tables — the circuit proves the function was evaluated from a pre-committed table of valid outputs. Expensive but well-understood.

LayerNorm and GELU (used in most modern transformers) are the hardest. GELU requires approximation; LayerNorm involves division by a square root, requiring an inverse square root range proof.

The asymmetry is the whole point: a proof taking 90 seconds to generate takes 3 milliseconds to verify — forever, by anyone, anywhere, with no access to your model.

05 — Practical sweet spot today
Do this now
Small classifiers
2–4 layer MLPs with <10K params. Intent detectors, small policy nets. Proving in seconds on CPU.
Do this now
Embedding attestation
Prove a CLIP / sentence-transformer embedding was computed correctly from a committed input. Very cheap — one linear layer.
Emerging
CNN image proofs
Small ResNets feasible with GPU. Prove an image passed a classifier without revealing the image. Content authentication.
Research
Transformer attention
Single attention heads provable with approximations. 2–10 min GPU proving per head. Softmax and LayerNorm need tricks.
For agents
Decision attestation
Prove a small policy / reward model output. An agent attests its action was valid without revealing its full state.
For LAP / AiM
Identity hash proofs
Merkle inclusion proofs on a committed LAP document. Prove identity consistency across sessions in <1s. No zkML needed.
Article 03 — Agentic Infrastructure

The Technical Stack
for Autonomous Agents

Autonomous agents can't just generate output. They have to transact — finding counterparties, making commitments, moving money, and operating inside market rules. This is the missing infrastructure layer. Three planes. Ten layers. Most of it not yet built.

Aaron Wright — May 19, 2026 · 69.5K views
The core argument
Markets don't run on intelligence. They run on identity, trust, pricing, contracts, settlement, enforcement, and policy.

Strip those away and you don't have an economy. You have a demo. The question underneath agentic capital markets isn't who funds an agent — it's what allows one software actor to reliably transact with another. Whoever assembles the full stack first will not just build a useful product. They will own the transaction rails of machine labour.

Plane 01 — Trust
Trust plane
Who the agent is, how it's found, what it has done

Three layers that must exist before any market can clear at all.

L1
Identity — Know-Your-Agent
Who is on the other side of the trade?
Current state: identifiers without identity. An agent introduces itself as gpt-4.1-claims-processor-v3 and you have no way to verify the weights match, the system prompt is what it claims, or the tools it advertises are accurate. ERC-8004 (August 2025, co-authored by MetaMask, Google, Coinbase, Ethereum Foundation) defines an Identity Registry as an ERC-721 NFT — each agent owns a token resolving to a JSON file naming its A2A endpoint, MCP endpoint, ENS handle, and wallet addresses. The soft underbelly: operators self-attest. Apple-style signing by inference providers doesn't exist yet.
ERC-8004 Cheqd Sphereon AgentProof
L2
Discovery & Capability Registry
How do you find the right agent?
Today: a flat list on a webpage with no machine-readable capability surface. An agent looking for "OCR under 200ms p95 with HIPAA controls" cannot ask that question to any existing registry and get a structured answer. MCP and A2A are the interop standards; ERC-8004's registration file is the closest thing to a structured capability declaration — each agent publishes its name, endpoints, trust models, and arbitrary metadata. The search engine layer on top does not yet exist as a category-defining product.
MCP (Anthropic) A2A (Google) ERC-8004
L3
Reputation
What has this agent actually done?
Agent work isn't commoditised — outputs vary, agents drift, models get deprecated. Reputation is load-bearing. Needs: cryptographically attested job histories, cross-marketplace portability (no marketplace currently lets reputation out — it's their moat), and sybil resistance. ERC-8004's Reputation Registry is the most concrete attempt: stores raw feedback on-chain, scoring happens off-chain. "Moody's for Machines" — a rating agency that turns raw feedback into investment-grade scores — has not been built and is one of the most valuable openings in the stack.

Plane 02 — Market
Market plane
How value clears between agents

Four layers for price discovery, obligation encoding, money movement, and dispute resolution.

L4
Quoting & Price Discovery
The layer that doesn't exist — and is the most economically interesting
Agent services don't fit hourly, fixed-scope, or outcome pricing cleanly. The interesting price isn't "per token" but "per result of acceptable quality." Needs real-time RFQ (buyer agent broadcasts job spec, providers respond in 100ms — Tradeweb for cognitive work) and outcome contracts with verifiable completion. The closest blueprint is programmatic ad exchanges. The companies building this are mostly stealth. The opening is large.
Largely unbuilt AgentOps (adjacent)
L5
Contracting
What exactly was the money supposed to buy?
Today: a prompt, an API call, a payment auth, and an assumption both sides mean the same thing. Enough for a demo; not for a market. Needs machine-readable MSAs (EIP-712 typed data is the right cryptographic primitive), encoded SLAs with signed eval prompts, proof of authority from the governance layer, and termination conditions enforceable without either side's cooperation. A real contracting layer looks less like a PDF and more like a hybrid object: part legal agreement, part workflow schema, part policy bundle.
EIP-712 Largely unbuilt
L6
Settlement
Money moves on agent timescales, not Net-30
Three rails compete: stablecoin (sub-second, programmable, jurisdictionally unsettled), agent-issued cards (Visa Intelligent Commerce, Mastercard Agent Pay, Stripe Issuing — bank rails with chargebacks, jurisdictionally clean), and ACH (cheap, slow, fine for weekly cycles). The right architecture is layered. Whoever builds the abstraction layer — pay(amount, currency, counterparty, settlement_window) and the system picks the cheapest rail — wins the developer surface.
Coinbase x402 Stripe Bridge Visa Intelligent Commerce Circle CCTP
L7
Dispute Resolution
When an agent doesn't deliver, who decides?
Today: "the human operator emails the other operator." Doesn't scale to a million agentic LLCs. Needs escrow as default (held until SLA conditions met), automated remediation (quality below threshold → automatic refund), and third-party validators. ERC-8004's Validation Registry is the standardised hook — intentionally unopinionated about how validation happens: zkML proofs, TEE attestations, stake-secured re-execution, or human judges. The arbiter is itself a marketplace participant with its own reputation.
ERC-8004 Validation Kleros (adjacent)
Plane 03 — Control
Control plane
What the agent is allowed to do — and what must be proved

Three layers for governance, compliance, and runtime coordination. The fastest-moving part of the stack right now.

L8
Governance
Spending limits, approval chains, kill switches, proof of authority
The most concrete primitives came from crypto first: Safe allowance modules, ERC-4337 session keys with scoped time-bounded permissions, hierarchical multisig with timelocks. The enterprise version: Cordum, Galileo, Microsoft's Agent Governance Toolkit — SOC 2-friendly, IAM-integrated. The deepest unsolved piece: authorized scope — a machine-readable, signed declaration of what the agent is allowed to bind its principal to. Without it, every agent-signed contract is one ultra vires claim away from worthless. Gartner predicts 40%+ of agentic AI projects will be cancelled by end of 2027 specifically because organisations cannot govern them.
Cordum Galileo Aegis AI Safe modules ERC-4337 MS Agent Governance
L9
Compliance
What must be proved to a regulator, after the fact?
Governance asks: what is the org willing to let the agent do? Compliance asks: what is the org required to prove about what the agent did? Different buyer (general counsel vs CISO), different SLA (real-time enforcement vs evidentiary completeness), different failure mode (bad outcome vs regulatory fine). The EU AI Act's high-risk obligations take effect August 2, 2026 with Article 99 penalties up to €35M or 7% of global turnover. Audit-grade logging (Articles 12 & 19) is similar in shape to SOX requirements — the same kind of GRC vendor stack is likely to emerge.
ComplyEdge Lucairn Agent Module AgentWorks
L10
Orchestration & Runtime
Where agents run, remember, get watched, and hand work to each other
Four distinct concerns that were wrongly conflated: Runtime (Modal, E2B, Daytona — differentiating on price and cold-start), Memory (Mem0, Letta/MemGPT, Zep — not yet portable across runtimes), Observability (Langfuse, Arize, Braintrust — the audit trail backing reputation, compliance, and disputes), and Orchestration (LangGraph, CrewAI, AutoGen, Anthropic Skills — where multi-agent state, handoffs, parallelism, and failure recovery get encoded). 59% of enterprises in 2026 run three or more LLMs that need to coordinate. OpenTelemetry-for-agents is the missing standard — the marketplace doesn't have to build the runtime, but it must standardise the export format.

Strategic read
The platform claim
Whoever owns identity, settlement, and governance owns the marketplace.

The ten layers compose. Identity unlocks reputation. Reputation unlocks pricing. Pricing unlocks contracting. Contracting unlocks settlement. Settlement plus governance unlocks enforceable disputes. Layer 4 (quoting) is the most undervalued — settlement gets the press, identity gets the standards work, governance has a wave of funded startups, observability has fifteen. Real-time machine-to-machine price discovery is a TAM measured in low-trillions of dollars of cognitive labour reallocating to software, and almost nobody is building it as a primary product.

What the winning company looks like
Not a model lab. A market operator.

Part exchange, part payments network, part identity provider, part trust infrastructure, part governance platform. Less like OpenAI and more like Visa, Moody's, Stripe, Nasdaq, and ServiceNow fused into a single system for software actors. That company does not exist yet. But the constraints around it are now visible, and the standards substrate — led by ERC-8004 — is starting to take shape underneath them.
